## 변경 사항

- Peek와 동일한 7개 언어: en, ko, de, es, fr, ja, pt-BR.
- 앱 문자열 256개, Info.plist 문자열 4개 전체 번역.
- 캘린더 전체 접근 권한 설명 추가 및 번역.
- 긴 번역을 위한 설정 창과 기간 레이블 공간 조정.
- 7개 언어 App Store 메타데이터 업로드 후 원격 값 일치 검증.
- 기존 main 작업의 계획판, 메모, 검색, 내보내기 개선 포함.

## 검증

- Release macOS 로컬 빌드 성공 (서명 제외).
- 7개 언어 전체 키·번역 상태·형식 지정자 검사 통과.
- 컴파일러 추출 UI 키 180개 전부 카탈로그에 포함.
- 빌드된 앱의 7개 lproj와 캘린더 전체 접근 권한 키 확인.
- 독일어 실제 실행: 연간 캘린더와 설정 화면 번역·배치 확인.
- 시간대 3개 × 514 회귀 검증 통과.
- 계획판 복제·삭제·마이그레이션·메모 보존 및 PDF·PNG·인쇄 검사 통과.
- CloudKit 실제 기기 간 동기화는 이 번역 변경에서 재검증하지 않음.

클라우드 빌드·심사 제출 결과는 태그 생성 후 별도 기록한다.

## 배포 경로 수정

- Xcode Cloud 태그 조건을 정확한 문자열 `v*`에서 접두어 `v`로 수정.
- `v1.2.0` 소스 커밋 `b29131c441ee4ccaf75ac4c736458372b5a8fab7`의
  Xcode Cloud 실행 `7ade92c7-47a0-4522-98d1-30adcce1c76d`를 시작.
- GitHub Actions에서 Ruby 3.3과 호환되지 않는 Bundler 1.17.2가 실패하여
  Gemfile.lock의 Bundler를 2.6.9로 고정. 바이너리 소스와 태그는 유지.
- GitHub OAuth 토큰에 workflow 권한이 없어 워크플로 파일은 변경하지 않음.
  태그 기반 심사 워크플로 대신 App Store Connect API로 동일 빌드를 제출.

- 추가로 CFPropertyList 3.0.9가 Ruby < 3.2만 지원하여 3.0.8로 조정.
  나머지 잠금 의존성은 유지.
- 일본어 연간 캘린더와 설정 화면 실제 실행 확인.

## 빌드 번호 충돌 해결

- 첫 실행은 Archive/Export에는 성공했지만 App Store Connect 준비 단계 실패.
- 동일한 클라우드 패키지 직접 업로드 결과 90061 오류로 원인 확인:
  Export 단계에서 Cloud 번호 1이 적용되어 기존 출시 빌드 9보다 작았음.
- Xcode Cloud 설정의 다음 빌드 번호를 2에서 10으로 변경하고 UI 저장 확인.
- 같은 릴리즈 태그로 빌드 10 재실행: `d8a896d0-a905-43c6-adcb-f9b0e743ba4f`.
